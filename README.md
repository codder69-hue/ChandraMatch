# ChandraMatch

Feature-based image correspondence and registration for Chandrayaan-2
imagery (OHRC, TMC-2). A classical computer-vision pipeline — feature
detection, matching, RANSAC-based outlier rejection, and homography
estimation — evaluated against real ISRO mission data, with a local web
interface for interactive use.

## Why classical CV, not deep learning

No labeled training data was available for this task, results need to
be inspectable at every stage rather than a black box, and the pipeline
needs to run on ordinary laptop hardware without a GPU. ORB/SIFT +
RANSAC + homography is the established baseline approach for this class
of problem, and the project's contribution is a complete, validated,
usable *system* built on it — real-data batch evaluation, automatic
overlap discovery, ground-truth cross-scale validation, and a working
UI — rather than a new matching algorithm.

## Features

- **Core pipeline** (`chandramatch_pipeline.py`) — preprocessing, ORB/SIFT
  feature detection and description, brute-force matching with Lowe's
  ratio test, RANSAC homography estimation, registration, and
  quantitative evaluation (inlier ratio, reprojection RMSE).
- **Real PDS4 support** — reads actual Chandrayaan-2 OHRC/TMC-2 products
  directly (`--pds4_1`/`--pds4_2`), including a `--inspect` diagnostic
  mode for PDS4's undocumented per-mission key naming.
- **Automatic overlap discovery** (`find_overlaps.py`) — parses each
  product's geometry CSV (lat/lon sampling) to find which scene pairs
  actually overlap on the ground, instead of guessing from filenames.
- **Batch evaluation** (`batch_run.py`, `analyze_results.py`) — runs
  every discovered overlapping pair through the pipeline, with
  crash-safe incremental CSV logging and per-scene image caching, then
  generates report-ready plots and summary statistics.
- **Cross-scale validation** (`cross_sensor.py`,
  `simulate_cross_scale.py`, `batch_simulate_cross_scale.py`) —
  estimates each scene's real ground-sample-distance from geometry data
  and scale-normalizes OHRC/TMC-2 pairs (~20x resolution gap) before
  matching. Includes a ground-truth simulation mode: real OHRC imagery
  is synthetically degraded to TMC-2's documented resolution under a
  *known* transform, so registration accuracy can be measured directly
  against ground truth rather than estimated.
- **Web interface** (`streamlit_app.py`) — upload-and-run pipeline in
  the browser, saved/comparable results across multiple pairs, a
  cross-scale validation dashboard, and a feedback form.

## Results

From 21 real overlapping OHRC scene pairs (42 registrations, ORB and
SIFT):

| | Mean inlier ratio |
|---|---|
| Same-day pairs (n=26) | 97.3% |
| Pairs spanning ~27 days (n=16) | 74.4% |

Correlation between acquisition time gap and inlier ratio: **-0.807**.

From ground-truth cross-scale validation across all 10 available OHRC
scenes (each degraded to TMC-2's ~20x coarser resolution under a known
transform):

- Mean inlier ratio: **98.7% (σ = 0.6%)**
- Median scale-recovery error: **0.37%**
- Median rotation-recovery error: **0.12°**

Figures: see `report_figures/` (generated by `analyze_results.py`).

## Setup

```bash
pip install -r requirements.txt
```

Windows users can run `setup_windows.bat` instead, which creates a
virtual environment and installs everything in one step.

## Usage

```bash
# Run on a synthetic self-test pair (no data needed)
python chandramatch_pipeline.py

# Run on two ordinary photos
python chandramatch_pipeline.py --img1 a.jpg --img2 b.jpg

# Run on real Chandrayaan-2 data (see Data section below)
python chandramatch_pipeline.py --inspect path/to/file.xml   # check structure first
python chandramatch_pipeline.py --pds4_1 a.xml --pds4_2 b.xml

# Find which downloaded scenes actually overlap
python find_overlaps.py --scan path/to/data

# Batch-run every overlapping pair and log results to CSV
python batch_run.py --scan path/to/data --detector both

# Generate report-ready plots and summary stats from batch_results.csv
python analyze_results.py

# Cross-scale (OHRC<->TMC-2) registration, given a real overlapping pair
python cross_sensor.py --geo1 ... --xml1 ... --geo2 ... --xml2 ...

# Ground-truth cross-scale validation on one real OHRC scene
python simulate_cross_scale.py --xml path/to/file.xml

# ...or across every scene at once
python batch_simulate_cross_scale.py --scan path/to/data

# Launch the web interface
python -m streamlit run streamlit_app.py
```

## Data

Chandrayaan-2 OHRC and TMC-2 data is publicly available from ISRO's
Indian Space Science Data Centre (ISSDC) via the Pradan portal:
<https://pradan.issdc.gov.in/ch2/>. Registration is required. Downloaded
products are not included in this repository (see `.gitignore`) — each
product is several hundred MB to ~1.2GB, well beyond what's practical
to version-control.

## Project structure

```
chandramatch_pipeline.py       Core pipeline + PDS4 loading
find_overlaps.py               Geometry-based overlap discovery
batch_run.py                   Batch registration across overlapping pairs
analyze_results.py             Plots + summary stats from batch results
cross_sensor.py                Cross-sensor (OHRC<->TMC-2) registration
simulate_cross_scale.py        Ground-truth cross-scale validation
batch_simulate_cross_scale.py  Batch version of the above
streamlit_app.py               Web interface
setup_windows.bat              One-step Windows environment setup
assets/                        Favicon and other static UI assets
saved_results/                 Curated demo results shown in the web UI
report_figures/                Generated plots (from analyze_results.py)
batch_results.csv              Real batch registration results
cross_scale_results.csv        Real ground-truth cross-scale results
```
